# Git and collaboration

Inspect `git status --short` before editing. Review only the paths related to the task and preserve pre-existing local changes, including installed project skills. Use `git diff --check` for tracked changes and inspect new files before staging.

Use the [pull request template](../templates/pull-request.md) when preparing a PR. Describe the learner-visible behavior or tooling outcome and the checks actually run. Include the tested revision for cloud verification.

Check `git remote -v` before using issue or PR workflows. This checkout had no configured remote at setup. Select the intended repository before publishing.
